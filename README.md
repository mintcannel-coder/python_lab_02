# StreamStats — потоковый анализатор логов

`streamstats` — Python-пакет для чтения и анализа файлов с логами. Он обрабатывает события из CSV и JSON Lines (JSONL), проверяет корректность данных и формирует статистический отчёт в JSON. Статистика из нескольких входных файлов объединяется в один отчёт.

Проект также содержит дополнительные возможности: ленивые фильтры событий, реестр парсеров для пользовательских форматов, сохранение отчёта в CSV, итератор для отслеживания дописываемого JSONL-файла и парсер учебного бинарного формата.

## Возможности

- Потоковое чтение файлов: обработка выполняется последовательно, без загрузки всего файла в память.
- Поддержка CSV с заголовком и JSONL — по одному JSON-объекту на строку.
- Проверка обязательных полей и допустимых значений событий.
- Объединение статистики из нескольких файлов за один запуск.
- Обработка повреждённых строк: остановка с ошибкой по умолчанию или пропуск с помощью `--skip-invalid`.
- Формирование JSON-отчёта с общим количеством событий, статистикой по уровням и источникам, топ-5 источников ошибок и временными границами.
- Дополнительные функции: ленивые фильтры, реестр парсеров, CSV-отчёт, отслеживание дописываемого JSONL-файла и бинарный парсер с использованием `memoryview`.

## Формат события

Каждое событие должно содержать следующие поля:

| `timestamp` | Временная метка в формате ISO 8601 | `2026-06-01T10:00:00` |
| `level` | Один из уровней `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` | `ERROR` |
| `source` | Непустая строка — источник события | `auth-service` |
| `message` | Строка с описанием события | `Authentication failed` |

### CSV

CSV-файл должен содержать строку заголовка с полями `timestamp`, `level`, `source`, `message`:

timestamp,level,source,message
2026-06-01T10:00:00,INFO,auth-service,User logged in
2026-06-01T10:01:00,ERROR,auth-service,Authentication failed

### JSONL

В JSONL каждый объект события занимает отдельную строку:

{"timestamp":"2026-06-01T10:00:00","level":"INFO","source":"auth-service","message":"User logged in"}
{"timestamp":"2026-06-01T10:01:00","level":"ERROR","source":"auth-service","message":"Authentication failed"}
Файлы следует сохранять в UTF-8. Unicode-символы в названиях источников и сообщениях поддерживаются.

## Использование CLI

Общий формат команды:

python -m streamstats analyze INPUT [INPUT ...] --format csv|jsonl --output REPORT.json

### Анализ одного файла

Для CSV:

python -m streamstats analyze logs.csv --format csv --output report.json

Для JSONL:

python -m streamstats analyze logs.jsonl --format jsonl --output report.json

### Объединение нескольких файлов

Передайте несколько путей после `analyze`. Статистика будет собрана в один общий отчёт:

python -m streamstats analyze app-1.jsonl app-2.jsonl archived.jsonl --format jsonl --output report.json

Все переданные файлы должны соответствовать выбранному формату.

### Обработка некорректных строк

По умолчанию при обнаружении некорректной строки обработка прекращается. CLI сообщает об ошибке с указанием входного файла и номера строки и завершается с кодом `2`.

Чтобы пропускать некорректные строки и продолжать анализ, используйте `--skip-invalid`:

python -m streamstats analyze logs.jsonl --format jsonl --output report.json --skip-invalid

В этом режиме для пропущенных строк записываются предупреждения `WARNING`, а количество пропусков включается в отчёт.

## Содержимое отчёта

JSON-отчёт содержит агрегированную статистику. Основные поля:

- `total_events` — общее количество обработанных событий;
- `levels` — количество событий каждого уровня;
- `sources` — количество событий каждого источника;
- `top_error_sources` — до пяти источников с наибольшим количеством событий уровня `ERROR` и `CRITICAL`;
- `first_timestamp` — самая ранняя временная метка;
- `last_timestamp` — самая поздняя временная метка;
- поле со счётчиком пропущенных строк, если использовался режим `--skip-invalid`.

Временные границы определяются по значениям временных меток, а не по порядку строк во входном файле. Конкретное представление отчёта задаётся реализацией пакета.

## Дополнительные возможности API

Помимо основного CLI, пакет включает функции для работы с данными из Python-кода:

- **Ленивые фильтры** по времени, уровню и источнику. Они позволяют последовательно отбирать события без необходимости создавать промежуточные списки всех результатов.
- **Реестр парсеров** — регистрация пользовательской функции-парсера и выбор парсера по формату.
- **CSV-отчёт** — сохранение уже рассчитанной статистики в CSV без повторного вычисления агрегатов.
- **`tail_jsonl_stream`** — итератор, который отслеживает дописываемый JSONL-файл и выдаёт новые полные записи по мере их появления. Незавершённая строка не обрабатывается до появления разделителя строки.
- **Бинарный парсер** — читает пакеты, состоящие из четырёхбайтового заголовка длины в big-endian и следующего за ним JSON-тела. При чтении тела используется `memoryview`.

## Обработка ошибок

В пакете предусмотрена общая иерархия исключений `StreamStatsError`, в том числе ошибки неподдерживаемого формата, некорректного события, неверной временной метки и конфигурации CLI.
